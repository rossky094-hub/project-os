# Project OS Alpha 产品目标

版本 0.1.0-alpha.2 · 桌面本地工作台

目标用户是在复杂代码或 AI 开发中失去全局方向的人。工作台让他从自己想完成的结果出发，理解现状、核对目标、看每轮真实变化、辨别差距，再选择一个有依据的下一行动。模型解释要能被人纠正；普通用户不应先看目录树或技术治理历史才知道本轮价值。

## 五项结果

| 目标 | 用户需要看见什么 |
| --- | --- |
| 可靠项目理解 | 程序理解的整体用途；来源支持的产品流程、实现模块与关系；缺口与未知。静态关系与真实运行调用分别标注。 |
| 人类目标核对与分解 | 人的原话、可确认的场景与条件、模块期望及代码职责；修正后相关映射、差距和建议一起更新。 |
| 实际运行验证 | 登记检查的真实命令、断言、输出和绑定；功能缺失、环境阻塞、行为失败、未知与限定通过分别呈现。 |
| 每轮连续追踪 | 本轮目的、目标版本、开发前后来源、实际结果与剩余问题；失败、人工修改和重开后能继续。 |
| 整体调整建议 | 先判断完整主线，找共同阻断原因，再选择局部修复或流程调整；一个当前优先行动及判断方法。 |

默认“整体目标”列出原目标、相关流程与模块、保存的期望、当前适用证明、开发轮次和优先差距。每项可以进入模块核对、源码、流程或相关开发，再返回整体。上方完整目标与整体判断常驻，最近局部报告折叠查看。模块数、轮次数与文件增长不计为业务完成百分比。

## 人与程序共同使用

显式登记范围后，程序解释用途、旅程、职责及差距。人核对总体愿望和模块期望，保存真实原话；新分析必须消费新的目标或反馈。材料变化后撤下旧绿色，保留历史，直到当前相关映射和证据重新成立。

实际开发先捕获来源起点，再登记本轮目的与目标关系。开发之后读取真实来源变化、登记结果并取得独立回执。每轮应解释：之前怎样、现在怎样、与目标有什么关系、有哪些实际证明、还差什么、下一步怎样判断有用。阅读五步的答案由读者填写，保存意见不代表自动执行开发或接受产品。

建议先判定整体问题，再定位具体差距。当多个模块受同一主线问题影响时推荐共同修复，而不是按模块堆优化清单。没有新反例时不重复实现已有恢复、导入或阅读能力。

## 验证边界

“实现存在”“限定条件通过”“实际用户结果符合目标”分别呈现。初次登记、确定业务含义及配置真实行为检查仍需熟悉项目的人参与。公开 Alpha 已有原案例的软件路径，独立新手理解、陌生项目稳定准确率和跨工具自动追踪尚未形成通用验收。保存目标与条件不是替人接受业务结果；没有实际事件的代理活动保持未知。

桌面文字、键盘入口和来源原件属于交付范围；手机界面不属于本版要求。
